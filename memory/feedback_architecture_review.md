实施前必须进行充分的架构规划，用户会进行多轮细致的审查，重点关注以下方面：

1. **消息队列语义**：消费者模型必须与业务语义匹配（竞争消费 vs 发布订阅）
2. **安全性**：注册权限限制、认证凭证、数据加密、限流、暴力破解防护
3. **数据一致性**：事务边界、消息确认机制、死信处理、幂等性、发件箱模式
4. **数据库设计**：字段语义明确（如 consumer_role vs user_id）、唯一约束
5. **部署一致性**：容器化所有组件、启动顺序、健康检查
6. **实现细节矛盾**：如"密码哈希动态生成"与"init.sql 静态文件"之间的矛盾

**Why**: 用户在两次方案审查中分别指出了 12+ 和 14+ 个问题，覆盖设计缺陷、安全漏洞、数据一致性和运维可靠性

**How to apply**: 架构规划阶段就应逐项检查上述清单，不等用户指出再修复；方案中避免矛盾声明（如同时存在两种密码初始化方式）
